## 1. Notebook grading benchmark

12 phone-photo-style notebook pages rendered by Muse Image from written specs (`evals/grading_specs.py`), 40 scored problems covering Class 2-6 addition, subtraction (incl. borrow across zero), multiplication, long division, fractions, decimals and 4-digit arithmetic, with 16 planted misconceptions. Labels are what is actually drawn on each page (checked by eye); right/wrong for each label is computed by sympy.

| Metric | Apni Gati pipeline | Model-only baseline (one Muse Spark call) |
|---|---|---|
| Right/wrong accuracy | 39/40 (98%) | 40/40 (100%) |
| Correct work marked wrong | 0/22 (0%) | 0/22 (0%) |
| Mistakes missed | 0/18 (0%) | 0/18 (0%) |
| Sent to teacher review | 1/40 (2%) | — |
| Problems found on page | 40/40 (100%) | — |
| Final answer transcribed exactly | 37/40 (92%) | — |
| Misconception diagnosed exactly | 13/15 (87%) | — (baseline gives no diagnosis) |
| Misconception at right concept/root | 14/15 (93%) | — |

Cost $1.30 for all pages; median 50.2 s per page (problems on a page run in parallel).

**Honest reading:** on clean pages Muse Spark alone already judges right/wrong very well (the baseline scored 40/40; the pipeline's single miss was sent to teacher review because the zoomed re-read could not confirm the answer, not marked wrong). What the pipeline adds is that every mark is *proved* by sympy rather than asserted, the first wrong working step is located and circled on the photo, the misconception is diagnosed against the NCERT concept graph, unreadable or incomplete problems go to the teacher instead of being guessed, and text on the page cannot change a grade.

Ambiguous case: `85 - 46`: subtrahend not drawn: only 85 and 39 visible → the right outcome is needs_review. Pipeline: **needs_review**, baseline: missed.

## 3. Root-cause agent (Muse Wonder)

10 simulated children with a hidden gap concept (`scripts/seed_demo.py`). Neither method sees the hidden gap.

| | Exact root | Within 1 prerequisite hop |
|---|---|---|
| Muse Wonder agent | 4/10 | 6/10 |
| Knowledge-tracing baseline | 3/10 | 3/10 |

Cost $0.73 total, median 14 s per child.

The baseline above uses the app's teacher-safe rule (a concept needs at least 2 observations before it is called a gap), so it often abstains. With a lenient single-observation rule the baseline scored 6/10 exact and 8/10 within one hop against the agent's 5/10 and 7/10 (run log `results/agent_run3.log`).

**Honest reading:** the simulator generates evidence the same way knowledge tracing models it, so statistics alone are a strong baseline; the agent is roughly on par on root identification. Its added value is that it always commits to a reasoned hypothesis using misconception evidence, explains it to the teacher, names an alternative, and writes sympy-verified probe questions to test the hypothesis on the child. Version history: v1 (agent fetched everything through ~20 small tool calls, server-side conversation state) failed on 4/10 children (expired server state, malformed probe, ran out of turns). v2 puts a compact evidence summary and the knowledge-tracing estimate in context, uses one subgraph tool, replays state client-side and forces submission on the last turn: 10/10 complete with 6-7 tool calls each.
